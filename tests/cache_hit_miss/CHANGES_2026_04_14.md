## Test tasarımı

### store/l1_hit

Stack line'ını L1'e sokmak için ROI **öncesinde** `x = 0` (volatile) yapılıyor.
Bu store `inside_roi = false` olduğu için SPILL_STORE sayılmıyor ama cache line'ı ısıtıyor.
Sonra `m5_work_begin` (leaf fonksiyon, stack erişimi yok), ardından ROI içi `x = 0xA5A5...` → **L1 hit**.

```
sd zero, 8(sp)     ← ROI öncesi, sayılmaz, line'ı ısıtır
m5_work_begin
sd a5,  8(sp)      ← ROI içi, SPILL_STORE → dcache.spillStoreHits++
```

Neden `x = prologue`'dan gelen `sd ra` yetmez?  
Compiler `x`'i `8(sp)`'ye, `ra`'yı `24(sp)`'ye koyuyor. `sp%64 = 48`
olursa bu iki adres farklı 64B cache line'larına düşer → prologue'un
dokunduğu line `x`'inkiyle aynı olmayabilir. Explicit pre-warm bu riski ortadan kaldırıyor.

### store/l1_miss

ROI açılmadan önce 32 satırlık BSS flush → main'in stack frame'i L1'den çıkıyor.
`m5_work_begin` (leaf, memory erişimi yok) → stack line hâlâ L1'de yok.
ROI içi store → **L1 miss**.

```
flush_l1()         ← 32×64B BSS okuma → main'in stack line'ını evict eder
m5_work_begin      ← leaf, stack'e dokunmaz
sd a5, 8(sp)       ← ROI içi, SPILL_STORE → dcache.spillStoreMisses++
```

`flush_l1` disassembly'si doğrulandı: hiç `sd`/`ld sp` yok, saf register döngüsü.

## Önemli keşif: SPILL_STORE L2'ye kadar taşınıyor

Başlangıçta "write-allocate RFO paketi SPILL_STORE flag'ini taşımaz, dolayısıyla
`l2.spillStore*` hep 0 olur" diye varsayılmıştı (önceki oturumdan ROADMAP/SUMMARY'de yazılıydı).

**Bu yanlış çıktı.** `store/l1_miss` simülasyonu şunu gösterdi:

```
system.cpu.dcache.spillStoreMisses = 1   ← L1 miss, beklenen
system.l2.spillStoreHits           = 1   ← beklenmeyen, ama doğru!
```

gem5, L1 write-miss için L2'ye gönderdiği `ReadExReq` (RFO) paketine
orijinal store request'in SPILL_STORE flag'ini **kopyalıyor**.
Dolayısıyla `l2.spillStoreHits` ve `l2.spillStoreMisses` anlam taşıyor.

Bu, **store tarafında da tam 4-sayaç görünürlüğü** sağlandığı anlamına geliyor:

| Senaryo | dcache.spillStoreHits | dcache.spillStoreMisses | l2.spillStoreHits | l2.spillStoreMisses |
|---|---|---|---|---|
| L1 hit | 1 | 0 | 0 | 0 |
| L1 miss, L2 hit | 0 | 1 | 1 | 0 |
| L1 miss, L2 miss | 0 | 1 | 0 | 1 |

Üçüncü satır (`l2.spillStoreMisses`) bir `store/l1miss_l2miss` testiyle doğrulanabilir
(160 flush line, tıpkı `load/l1miss_l2miss` gibi).
